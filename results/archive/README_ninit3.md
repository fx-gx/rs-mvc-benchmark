# 归档：n_init=3 代理协议下的扫描

这四份 journal 是 **2026-10-07 ~ 08 用 n_init=3 扫描**出来的记录。

**为什么作废**：换 n_init 不只改数值，**还会改变配置之间的排名**。实测：
- Salinas：扫描冠军 λ=1 γ=0.01（0.6374）在 n_init=10 下只有 0.6253，掉到第 3；
  而扫描第 **8** 名 λ=0.1 γ=1 复核后成为冠军（0.6325）。
- MUUFL：扫描冠军 λ=1 γ=0.1（0.4193）复核后 0.3994，**反不如官方基线 0.4069**；
  扫描第 4 名 λ=1 γ=10 成冠军（0.4146）。
- Trento：λ=10 γ=1000 从 0.8705 **暴跌到 0.7412**（−0.1292）。

**结论**：低 n_init 只是"读出协议"不同，不是更快的等价算法——用它做代理是拿正确性换速度。
只复核冠军（原 Stage C）防不住整表翻转；只复核 top-8 也只是减轻、没有消除
（第 8 名能变第 1 名，第 9 名以后同样可能更好的）。

**现行做法**：整张网格一律在正式协议 n_init=10 下扫描
（`scripts/tune_osmagc.py --n-init 10`）。这两份 journal 仅作历史留存。
